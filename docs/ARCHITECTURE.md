# Architecture

The broadcaster is an authenticated Valheim client using the existing main camera, game AudioListener and an owned FFmpeg process. Ordinary players need no broadcaster mod. The optional dedicated-server companion establishes a read-only connection and supplies discovery to that authorized observer. The 0.8.0 autonomous layer uses the same protected character/interest carrier that the user exercised in 0.7.0; the separate bodyless-spectator branch is not integrated here.

The 0.8.16 camera director shares one Cinemachine pipeline across player, creature and scenic coverage. `CinematicShotInput` identifies the scene kind; observed actors provide `CameraSceneFrame` data, while scenery provides an immutable `ScenicShotPlan`. The common rig owns damping, candidate selection, physical validation, composition and continuity. Actor trajectories remain separate from live aim targets; environmental camera and aim paths develop independently. Probe viewing remains a fixed measurement, and travel/recovery remain held-frame or slate presentation. See [CAMERA-DIRECTOR.md](CAMERA-DIRECTOR.md) for controls, mode behavior and runtime validation.

Version 0.8.17 adds an optional observed-idle wildlife policy on top of that pipeline. Complete fresh activity for every connected ordinary player must establish at least 60 seconds of inactivity before a nearby loaded creature can temporarily replace player coverage. Local activity vetoes and at least 60 seconds of rearm keep the policy subordinate to player activity. It does not change observer admission, simulation ownership, empty-server behavior or world time.

Version 0.8.18 builds directly on `94fb4a1`. Shared `PictureQuality` decisions make readable footage the priority for selection, movement, transitions and coverage credit. Structural room/opening measurements remain separate from dungeon-layer readiness. Shot intent, observed locomotion and transition policies choose bounded scale/response; supported group-primary handoffs retain scene identity and trajectories. Player scheduling uses fresh activity, bounded encounter retention and fairness. A separate optional `Events1` server feed adds remote observation without changing admission protocol 3 or the 0.8.17 idle feed.

Version 0.8.19 builds directly on 0.8.18 (`4ecea7d`). `ShotLongevityPolicy` ranks bounded future visibility among presently readable views; `ShotSequencePolicy` and `ShotContinuityPolicy` preserve usable-footage beats and screen geography. `ShotScalePolicy` explicitly validates wide/full/qualified medium actor envelopes. `FrameHold` supplies clean program output before overlay UI, while `RenderedPictureMonitor` samples that live output for conservative exposure/contrast feedback. These changes are client-side and preserve all existing protocol and simulation boundaries.

Version 0.8.20 builds directly on 0.8.19 (`6fbfb9d`). Native `CinemachineClearShot` ranks the existing evaluated camera states through a narrow temporary quality bridge; the director retains presentation-qualified timing and validated adoption/rollback. Native `CinemachineConfiner3D` uses a verified interior camera cell in a separate, unsimulated physics scene. Native `CinemachineSplineDolly` traverses finite scenic paths with no second body owner, and `CinemachineBlend` supplies interpolation curves. The camera adapter continues to validate the complete resulting view and path. The clean-feed regression is addressed by calibrating GPU readback row order before automatic streaming rather than assuming a backend orientation or inheriting a prior manual flip workaround.

Version 0.8.21 builds directly on 0.8.20 (`94e563f`). Native Position Composer owns screen/depth response for a distinct fixed-direction observational actor family. Group Framing can retain validated open-space translation before changing FOV; failed movement falls back to lens-only framing at the original pose. FreeLook Modifier coordinates eligible elevation profiles with explicit lens, damping and composition ownership. Final actual-picture and swept-path validation remain authoritative, and no observer protocol or server behavior changes.

The client plugin targets .NET Framework 4.8; the core targets .NET Standard 2.0. Jötunn 2.30.2 is the pinned compilation dependency. Builds read real matching game/BepInEx references and exclude Jötunn template deployment/publicizing hooks. CI does not launch the game. Game, Unity, BepInEx and Jötunn DLLs are excluded from project artifacts. The client intentionally includes the isolated `ValheimBroadcaster.Cinemachine.dll` built from pinned Cinemachine 3.1.7 sources, plus upstream notices. Selected official Unity Splines 2.0.0 runtime source is compiled into that same isolated assembly, with its own license/source record; no game Splines DLL is redistributed. The server does not reference or ship Cinemachine.

`FrameHoldRenderer` is appended to the active game camera's existing image effects. Its `OnRenderImage` callback caches the processed camera source only when that same frame's camera/carrier operation passed readiness. Live and Hold both blit that cached texture to the supplied camera destination. The hold never passes through screenshot capture or `GUI.DrawTexture`; GUI adds current status/recovery text only. The hold uses one cached render texture and GPU copies without another camera render. Separate bounded asynchronous readbacks supply streaming and optional actual-picture measurements. Streaming copies the current compositor texture before operator IMGUI/overlay UI. It uses the same clean live/hold texture or an owned recovery card, never a final-screen screenshot fallback. World-space UI already drawn into the camera remains scene content; the existing HUD controls still apply.

`ProgramFramePolicy` accepts a clean camera picture only from the current Unity frame with bounded age. Missing camera rendering supplies the recovery card even if an older held texture still exists. A program generation changes on resize, reset, camera loss and hard boundaries; late streaming readbacks are discarded. The fixed output texture belongs to the outstanding request until its callback finishes. GPU copy helpers restore render target and sRGB write state. Automatic orientation calibrates the camera-RT and slate-Texture2D copy/readback routes before encoding, verifies top-first rows, and ignores the saved legacy manual flip. Explicit FFmpeg flipping remains available only when automatic orientation is disabled.

A cached texture matches the source dimensions and graphics format; resizing, lost textures, camera replacement, stop and world cleanup invalidate it. Held/slate outputs never refresh the 0.75-second capture deadline. Hard travel/recovery boundaries clear that deadline immediately, preventing pre-travel footage from reappearing after a quick return to Watching. GUI requires a compositor result in the current frame and otherwise covers the display with a recovery slate. Valheim's built-in pipeline and existing image-effect stack were inspected; conflicting third-party camera effects or replacement render pipelines require separate runtime validation.

`broadcast framehold test` schedules a 0.5-second artificial readiness gap after two seconds, for closing the console. It changes presentation only: camera/carrier/director logic continues normally. Hard failures take precedence, and camera changes/stop cancel the test. It requires a live picture and can run while alone.

`RenderedPictureMonitor` receives only clean live-frame notifications. It makes an immediate 96×54 copy and reads it at up to 2 Hz with one request in flight. The callback must still match the program generation and current scene/shot identity. Global darkness/clipping and projected-primary versus surrounding-region contrast provide a small persistent editorial penalty. Mirrored ROI handling is conservative about backend row origin; it is not pixel segmentation. Holds/slates clear picture evidence. The monitor is independent of RTMP and releases owned textures only after pending reads complete. It neither changes scene lighting nor upgrades an unrendered candidate's readability.

## Shared procedural cameras

Player, creature and scenic coverage use Cinemachine 3.1.7 virtual cameras, solved explicitly from the existing game-camera postfix. No second rendering camera or Cinemachine Brain owns the game camera. An isolated dependency assembly and a small manual-update bridge advance Cinemachine's frame clock and preserve its duplicate-update guard. The adapter validates the resulting position before applying it to Valheim's main camera; the existing carrier/listener and frame compositor then follow their normal sequence.

Actor candidates vary preferred angle, distance and height; creature offsets scale with observed body dimensions. Six ordinary player candidates can compose a shared group, while four compact candidates retain only the primary. Eight extra compact recovery slots activate after sustained unreadability and sweep bounded standby directions without changing the live candidate’s search direction. Creature coverage currently frames one primary actor. Scenic candidates follow independently sampled world camera paths with separate environmental aim points and small alternative viewpoint offsets. The custom `FoliageShotQuality` extension implements Cinemachine's shot-quality interface and combines the resulting camera composition with read-only local visibility estimates. `PlayerShotVisibility` uses seven width-distributed primary body samples, three per companion and thirteen weighted foreground rays up to ten metres. Solid camera/near-plane overlap makes a candidate physically invalid. Collider-free foliage contributes explicit picture-health evidence and a bounded quality penalty; an obscured but physically safe image remains available while another angle is sought. It does not turn foliage into a loading or teleport decision.

The vegetation survey keeps up to 512 nearby renderer bounds, deduplicates LODs, checks live moving bounds and culls bounds per view. Normal refresh is three seconds or ten metres of movement; a recovery request can accelerate it with a 1.5-second minimum survey interval. Actual queried endpoints determine survey completeness. Bounds are conservative, not leaf-alpha measurements, and name/component classification can miss custom vegetation. The foliage evaluator does not change world colliders, renderers or shaders. Cinemachine can create a private hidden scratch sphere for penetration queries; its Rigidbody has collisions disabled, and the isolated runtime releases that cache idempotently on teardown. Visibility tests use bounded nonallocating physics buffers. The camera rig validates loaded support geometry and reachable carrier destinations separately from picture quality.

`CinematicShotDirector` adds usable-footage pacing, bounded decorative motion, recent shot history and activity/space-dependent settling. Visibility corrections take precedence over planned changes. In steady mode, `ProceduralShotPolicy` retains a clear current shot unless another improves quality by at least 0.15 for 0.5 seconds; healthy shots receive two seconds of minimum dwell. Physical invalidation can switch immediately, and poor shots can escape dwell. Motion prediction and smoothing reset on binding changes and discontinuities. The interpolated movement is checked before presentation; an unsafe blend can cut to a validated endpoint rather than pass through a wall.

`ShotTrajectoryPolicy` owns each orbital actor candidate's world-space follow anchor. The actual primary/group remains the look-at target. Shot intent and sustained scene movement determine trajectory development; bounded velocity/acceleration and continuous framing/range feedback keep the subject reachable without copying every position sample. The previous `velocity * 0.2` follow-point prediction is removed. Outgoing shot transitions no longer add the primary's exact displacement. Preview validation uses the planned trajectory, and the final pose still passes clearance, scene-support and carrier-reach checks.

`ScenicShotPlan` supplies the camera and aim paths for lateral, arc, lift, reveal and approach shots. Scenic motion is not inferred from a moving synthetic actor. Native Spline Dolly owns distance-based scenic Body movement by default, while Rotation Composer and a landscape guide place the observed terrain feature. Orbital Follow is retained as an explicit comparison fallback. Its evaluator uses the actual quaternion, FOV, aspect and near plane, measures feature visibility and foreground obstruction, and does not apply humanoid height/headroom rules. Dynamic/steady and motion-strength changes preserve the developed viewpoint instead of resetting to the path origin.

Observational candidates instead use `CinemachinePositionComposer` as their sole Body, following the actual primary point with fixed viewing orientation. Screen and depth guides latch for the observational binding, so instantaneous player motion cannot rewrite the preference. Native response permits drift inside those guides and damped correction outside them. These cameras bypass the custom trajectory controller and Rotation Composer; visibility/path rejection and alternative selection remain active. Unsupported context returns those slots to orbital behavior. Forecasts that do not model native composer history are treated as unknown rather than inventing a recentered future view.

`NativeFreeLookProfiles` installs a stable modifier value source before native body components. Orbital shots delegate elevation to Orbital Follow; supported scenic rises use native spline distance progress. Native Lens and PositionDamping modifiers operate at pipeline entry. The existing bounded placement policy supplies the middle guide after Body, then a deferred wrapper applies upstream CompositionModifier once before Aim. Native Finalize and a solve-finally guard restore temporary component settings, preventing accumulated offsets. Group framing owns group FOV; observational, confined and recovering views do not receive a competing profile.

`ShotCompositionPolicy` maintains a separate screen-placement preference for each actor candidate. Sustained screen-space motion, observed body facing and confidence-qualified activity points provide lead/activity room; persistent evidence and easing avoid immediate side changes. Projected subject/group extents constrain the guide to a safe envelope with headroom. Limited space and recent corrections restrain placement. Damping and the aim dead zone remain active around that guide, including when deliberate composition is disabled for comparison.

`CinematicLensFraming` reuses Cinemachine's bounded group-size calculation after the orbital Body stage. Qualified open-space groups use Dolly Then Zoom, retaining the full native translation only after validating its displacement budget and swept route. Unsupported or rejected movement recomputes ZoomOnly framing at the original body position; rejection starts a bounded retry delay. Native recentering rotation is suppressed so `RotationComposer` can apply deliberate placement at Aim. Native framing history is reset without clearing unrelated body/aim damping when switching back to zoom. Group offsets stay smaller and account for primary displacement from the shared anchor. The adapter includes dead-zone slack in the projected envelope, converts Y-up projection coordinates to Cinemachine's Y-down guide, and keeps hard limits centered on the actual image. A lost primary or inadequate safe-frame/headroom result triggers bounded relaxation toward primary-centered framing. This seeds the aim history without resetting position damping, then retains the corrected preference for three seconds. Large viewpoint changes use validated cuts, and healthy-view selection penalizes reversals across the observed action axis.

The evaluator measures the explicit required envelope from character dimensions, with visible/safe fractions, readable height and headroom. Wide/full and companion views retain the full body; qualified medium primary views require the upper-body envelope including head and torso. Intentional lower-body cropping does not relax head/torso or companion visibility checks. A centered and a thirds composition can receive the same framing quality when both fit; group coverage cannot compensate for a tiny or clipped primary. Diagnostics distinguish requested placement, applied guide and measured primary focus in the final presented pose. These measurements are picture-quality evidence, separate from physical clearance and scene readiness.

`PlayerSceneContext` supplies filtered body orientation and short-lived interest evidence. Resource points require a nearby actual ray hit on a recognized tree/rock collider during a recent attack; opponent points use the existing relevance checks. A work label alone does not supply an invented target. A supported primary handoff within an admitted, fresh, structurally connected group preserves scene identity, member weights and observation history. Unrelated primaries, world changes, respawn and discontinuities reset context. Replicated crafting animation and a directly supporting vessel can add evidence without inventing exact task or intent. These local observations require no new server deployment. `CreatureSceneContext` supplies one loaded living character with real `GetHeight`/`GetRadius` dimensions, filtered three-dimensional movement, body facing and bounded attack evidence. It does not infer a herd, claim a remote combat target or give player-coverage credit.

Player autonomous frameability and travel displacement query this same camera adapter's geometry. These queries remain finite and independent of foliage quality for finite known positions. The final applied camera/carrier still obeys the existing 95m/100m movement safeguards. The existing serialized `Camera.ProceduralPlayers` key now enables/disables the shared production pipeline; false selects legacy fixed framing for comparison. Its name is retained so existing configuration values survive. Camera mechanics do not change authorization, simulation isolation or streaming behavior. The optional 0.8.17 activity exchange is separate from admission/discovery/context protocols.

## Observer connection boundary

`RemoteObserverClient` pins `ObserverConnection` when the actual server connection opens. When true, a prefix on native `SendPeerInfo(ZRpc, string)` sends protocol-3 observer intent over that exact server RPC before the vanilla authentication packet. Both messages use the same reliable FIFO Steam transport. No vanilla packet is extended or rewritten. Object publication and gameplay routed calls are blocked before the local character can be published. The existing Hello/Reply endpoint names are retained for explicit version rejection; authorization still occurs only after native authentication. The client ownership predicate remains false for non-avatar world objects. When false, no observer request is sent and these guards do not affect ordinary gameplay.

The dedicated Steam server reserves only connections that explicitly request the matching observer protocol before native admission. `ObserverAdmission` locks ordinary admission at the start of `RPC_PeerInfo`; a late request cannot turn an already admitted player into an observer. Steam-ID allowlist membership alone never reserves a role or starts a handshake timer. Pre-authentication intent only adds restrictions: normal Steam authentication/readiness and the actual transport identity's allowlist check precede acknowledgement and discovery access. Requested but unauthorized observers are disconnected. The server drops observer object writes and character IDs, permits only a bounded authenticated native `RequestZDO` read, accepts only a finite bounded world-interest coordinate from player metadata, and refuses observer world ownership. Filtered gameplay peer enumeration excludes observers from player lists, random events and peer-driven zone generation. Native capacity uses the real ready connection count, so an observer still consumes a slot.

The role cannot be removed mid-connection. Revocation/timeout disconnects while restrictions remain through cleanup. Return/off parks the multiplayer carrier with protections intact; resuming camera coverage does not make it an ordinary player. Plugin shutdown disconnects observers before removing guards. An ordinary client never needs a renderer patch to hide the broadcaster because no broadcaster character is published to it.

This is a boundary around audited vanilla paths, not a sandbox for arbitrary third-party direct RPCs or conflicting Harmony patches. Other-client visibility, interactions, sleep and ownership handoffs remain runtime checks. Dormant regions are not simulated/generated merely for an observer.

## Authenticated discovery

Discovery is a read-only request/reply protocol available only to confirmed observers. `DiscoveryEnabled` controls delivery; `SharePrivatePlayerPositions` determines whether server-known non-public locations can be sent. This setting is a server policy distinct from the ordinary player's public-map flag. With sharing disabled, a private player remains present without an acquisition coordinate.

The player ID is the connection session UID; character ZDO identity is separate so respawn does not become a new connection. `IsSpawned` means the server has a character ZDO, not that the observer has loaded its scene. Positions come from the real character ZDO and require a recent player-metadata heartbeat. The client still requires a living instantiated player, loaded scene and viable camera/body geometry before presenting a player shot.

The client polls every two seconds, the server answers at most once per second per observer, and local snapshots expire after ten seconds. Sequence/world checks reject replayed, reordered and cross-world messages. The codec validates its inner payload before collection/string allocation: 32 KiB, 64 players, 128 regions per page, 64 UTF-16 characters/256 UTF-8 bytes per string. Native ZRpc/ZPackage deserialization occurs first; this application protocol does not protect against arbitrary native allocation flaws or a malicious server. Client region cache and server generated-region catalog are bounded at 1024 and 4096 entries respectively, with rotating pages.

Scenic candidates use the existing generated-zone set, procedural terrain height and biome queries. A persistent coordinate cursor makes at most 1024 cheap probes per second, with bounded nearby-peer seeds and at most 32 terrain queries per second; half the terrain-query budget is reserved for global progress. The cursor continues as the generated-zone set changes. A destination is a dry-land center with a generated 3×3 zone neighborhood, finite height above water plus two metres and strictly below 1000 metres. These queries do not instantiate server content. Local arrival/terrain/camera readiness remains a separate requirement.

## Optional activity events and fair selection

The 0.8.18 companion adds independent `EventRequest1` / `EventReply1` messages under `Observer.EventsEnabled=true`. The authenticated, confirmed-observer path reuses existing one-second passive samples; it does not add world scans, spawn actors or claim ownership. Entries carry bounded ages for movement, generic action, health loss and work/crafting, with at most 30 seconds of history. The client polls every two seconds and requires source/heartbeat/receipt freshness below six seconds. Private-position sharing policy is honored. Events are bounded to 64 players and 65536-byte packets with identity, world and sequence validation. Unsupported/disabled/failed event delivery leaves local camera and scheduling evidence available; it never changes observer admission or the separate idle-activity feed.

`PlayerActivitySelection` qualifies evidence for two seconds before weighting ordinary rotation choices. It favors supported active scenes and loaded alternatives, while an unshown player waiting 120 seconds takes priority over activity and encounter retention. The threshold is not a strict global waiting-time guarantee. Locally corroborated combat can retain a readable scene for at most 20 wall seconds beyond normal dwell, including up to three seconds of aftermath. Unknown damage/action never becomes proof of combat; a player attack beside a passive enemy cannot qualify on its own. Manual next/previous, exact selection and hold remain authoritative.

Sustained unreadable player footage has a separate 12-second failed-view budget. Only another already-loaded directly reachable player can replace it on that basis, with a 30-second failed-view retry cooldown. No local alternative means continued camera search, not quality-triggered travel. A readable image or hold resets failed-view timing. Foliage and composition do not modify scene readiness or carrier travel permissions.

## Optional all-player activity evidence

The 0.8.17 companion adds `ValheimBroadcaster.Observer.ActivityRequest1` / `ActivityReply1`. Admission stays at protocol 3, discovery at 2 and optional camera context at 1. Only authenticated confirmed observers can request this passive evidence. Snapshots retain every connected ordinary player, including unknown/unspawned entries; world, sequence, identity, source age and roster completeness must be valid before the client can permit a cutaway. An older companion can omit this exchange without breaking player coverage.

Activity comes from existing replicated movement, action, station/crafting, blocking/emote and health evidence. Source-observed idle duration is never extended merely by receiving a packet or waiting locally. Loaded-player activity can veto server inactivity immediately. Raw input and quiet inventory/menu interaction are not known, so the state is explicitly observed inactivity rather than proof of AFK. No ordinary-player mod or simulation activation is involved.

## Autonomous direction

`AutonomousDirector` receives immutable player/region snapshots, monotonic time, carrier position, actual presented-player identity and ready-idle footage. It returns a selected subject, reason and a tokenized travel request. The adapter accepts each request once, invokes protected native travel and reports completion/failure. One immutable destination remains in flight; changing player coordinates or manual selection cannot stack teleports.

Players are selected by stable ID with fair rotation across both ready nearby and fresh distant candidates. Viewing time advances only when the selected player's frame was actually ready/presented. A long update cannot charge hours of unseen footage: per-tick footage accumulation is capped. An unavailable target enters acquisition; the default 65-second attempt covers native travel and character readiness and permits at most three relocations. Arrival does not reset the attempt. Failed targets receive exponential cooldown starting at 30 seconds and capped at ten minutes, including the lone-target case.

While a player lacks a usable position/scene, the shot layer can retain valid idle coverage. Missing or expired discovery does not authorize stale travel. Death, respawn, portal movement and disconnect require new binding/readiness checks. Holding pauses automatic rotation/scenic transfers while the selected player's scene still requires validation. Manual selection changes are applied coherently after native travel completes.

Without a usable player, ready idle footage accumulates toward the 120-second region interval. Afterward, or after a separate ten-second unready-region seek interval, the director selects a fresh generated region within the configured 256–10000 metre distance range. It records bounded visit/failure history (128 entries each), applies the default 30-minute revisit interval and reports cooldown/catalog exhaustion. Unexpired region visits are never evicted to make room; a full history waits for expiry instead of permitting an early revisit. It does not promise unlimited novel content from a finite generated world.

The solo route exercise accepts 1–32 explicit marks and uses the same tokenized travel callbacks. Each destination must produce three seconds of ready scenic footage after arrival. A failed destination stops the route with a retained result. This is an acquisition/travel test, not a fake player, replication test or server mutation.

## Carrier and scene lifetime

Scenic selection ranks a bounded batch of loaded terrain candidates instead of accepting the first clear path. It samples six direction/height variants, checks nine points across the maximum motion envelope and validates swept camera segments. Terrain-only grounding avoids treating a tree or building collider as landscape ground. Environmental quality combines feature visibility, foreground openness and a modest measured-relief preference. Shown-place/style history discourages repeats only after actual usable footage.

`ScenicVisibility` caches up to 512 nearby vegetation renderer bounds, refreshed on cadence or movement, with LOD deduplication and bounded nonallocating physics buffers. The actual rendered orientation and lens determine foreground screening. Solid camera or near-plane overlap is physical invalidity; vegetation and a hidden/offscreen environmental feature lower quality. Cache truncation lowers survey confidence rather than certifying unseen positions. This is conservative bounds geometry, not pixel/alpha analysis; unfamiliar custom vegetation can be missed. No world renderer or simulation object is changed.

Replacement search retains the current plan and its developed progress instead of rewinding or discarding a still-valid picture. Persistent poor footage starts a bounded search before the compositor's hold window expires; exhausted searches remain retryable. An accepted replacement has a new monotonic plan ID and restarts scenic dwell, while the shared rig validates its handoff from the displayed pose. Region resets, travel and world changes remain explicit discontinuities.

The camera-relative carrier is a live local player kept two metres below a ready broadcast camera. Input/player update paths are suppressed only for that carrier; local god/ghost flags and Rigidbody gravity/collision/constraints are enforced. Body, character ZDO position and network interest move together. World objects remain outside observer ownership.

Immediate body following is bounded to a ready destination within 100 metres. The automatic adapter accounts for camera offset before treating a nearby target as directly frameable; larger moves require native travel. `Player.TeleportTo` and the private native teleport update perform distant travel. The policy waits for teleport completion, loaded destination and proximity rather than treating a coordinate as arrival. Each native trip is bounded to 45 unpaused seconds.

Before `ZNetScene.RemoveObjects`, a retention guard requires the local carrier ZDO in the near/distant retained lists. An excluding pass is skipped and travel suspended before the carrier can be destroyed. This is containment of stale interest/removal lists, not dual-region retention. The reference-only experimental probe remains separate and cannot run concurrently with observer travel.

Explicit return cancels the owned teleport and returns to the activation point. Multiplayer completion parks with protections retained; offline completion restores normal flags/controls. Explicit off cancels autonomous, stream and reconnect intent. Automatic failure recovery may request a protected return and resume only through its internal recovery flag. It is bounded; repeated failures request armed connection recovery or retain a protected suspended state with diagnostics.

World exit/destroy releases owned references, restores saved local flags/camera/HUD and stops the owned encoder. It cannot promise that a native return completes during world teardown. This distinction is why internal recovery and explicit user stopping are separate intents.

## Local shots and presentation

`CoverageDirector` chooses the actual player, scenic, creature or recovery shot; `IdleShots` searches within the loaded region. The survey origin is a search boundary, never an indefinitely repeated camera focus. Scenic paths have separate camera/aim movement and bounded shown-location/style memory. Creature discovery retains at most 32 nearest eligible loaded living non-player characters in deterministic order; stationary actors remain eligible. Observation never wakes dormant AI or changes simulation ownership.

Idle dwell and scenic progress require recent live compositor output matched to the coverage mode, revision and current scenic plan ID, plus a usable image from the common rig. Held images, slates, rejected views and proof from a previous plan earn no footage. Creature history is recorded on actual presentation; during normal idle coverage, a loaded creature without usable footage for three seconds returns to scenery with a separate 30-second failed-view cooldown rather than a five-minute shown cooldown. Ready players preempt normal idle coverage. The observed-idle wildlife exception is an authorized cutaway after complete fresh evidence that all connected ordinary players have been observed idle for 60 seconds. Autonomous region timing consumes the same usable-idle proof and retains its existing generated-region, travel-distance and cooldown constraints.

A wildlife cutaway uses eligible already-loaded creatures near the selected player, existing usable creature dwell and shown/failure cooldowns. Activity, stale/incomplete evidence, a roster change or lost creature resumes player coverage/acquisition; no eligible creature leaves player coverage in place. Rearm is at least 60 seconds. Hold, self-follow, probe and route operations suppress it. Empty-server scenic behavior, travel permissions and simulation clocks are unaffected.

Ordinary mode/subject/path changes no longer unconditionally destroy the camera pose. The shared rig can preserve a fresh displayed pose for a validated same-world handoff; unsafe transitions use a validated cut. Held/live re-entry starts from the view actually displayed, including when the candidate index is unchanged. Full resets still apply to world changes, controlled travel, explicit probe boundaries and restoration.

Initial player acquisition requires full `ZNetScene.IsAreaReady` at the subject, camera and carrier. This native predicate includes known network objects throughout a 3×3 zone neighbourhood and can fail during background object creation even when the displayed scene is usable. Once a complete player camera/carrier operation succeeds, `PlayerFollowContinuity` permits continued presentation for the same subject/character binding, using the last accepted position rather than the acquisition origin. At most one second may have elapsed and the target must have moved no more than 16 metres in 3D since the last presented frame. These are discontinuity limits, not a total follow radius. Candidate probes cannot renew the evidence.

The adapter additionally binds the actual Player instance, ZDO ID, world, local carrier and interior/exterior state. Death, missing/replaced actors, shot changes, stop/reset, travel and discontinuities require new acquisition. Selection, the autonomous policy, camera and carrier all use the same continuation decision. A continued shot checks existing generated terrain meshes/collider outdoors; in interiors it checks nearby static support geometry at interior height, excluding characters and rigidbodies. Camera support is checked at the actual smoothed/clipped position, then at the carrier: an unrealized desired offset beyond a tile boundary or small room must not veto an otherwise valid picture. A terrain tile far below an interior is never sufficient. These are scene-support checks, not proof of complete replication or artistic shot quality.

Full readiness remains the default for initial acquisition, scenery, creatures, probes, travel and return. Continued following still requires finite coordinates, local actor availability, loaded support geometry and the existing immediate carrier movement limits. Actual missing geometry can still produce a held frame or slate. The main and sky camera settings and normal HUD state are restored on stop. Child renderer/light/audio masking affects the local carrier; server publication guards provide the network visibility boundary.

`FrameHold` keeps one validated camera image on the GPU. Readiness gaps can display it for less than 0.75 seconds after its actual capture. Travel and explicit fault states bypass the hold for an honest slate. Resize, stop and world changes discard the texture. Capture failures disable the hold for that activation and retain the slate fallback. Diagnostics distinguish held frames from slate frames and retain the last readiness reason.

Observer lifecycle (`Watching`, `Travelling`, `Returning`, `Parked`, `Suspended`) is reported separately from programming (`Following`, `Acquiring`, `Scenic`, `Waiting`, route exercise), discovery freshness and recovery. Seeing `Watching` alone is not evidence of a human target.

## Audio/video and output recovery

`StreamCapture` copies the clean camera-compositor program texture at end of frame, blits to the output dimensions and requests asynchronous RGBA32 GPU readback with one request in flight. A latest-frame mailbox swaps three reusable arrays so receiver latency cannot create a frame backlog. The game AudioListener follows the broadcast camera, and `GameAudioTap` copies its mix into a bounded stereo ring without changing local playback or calling Unity/network APIs on the audio thread. Mono is duplicated; unsupported layouts fail clearly.

Video and audio workers use the same monotonic clock. Video is paced at configured FPS and audio in 20 ms blocks; short underflow inserts silence/repeats a frame. Excess audio backlog, prolonged missing callbacks or encoder lag fails the session rather than growing memory or hiding indefinite drift. Stop kills the owned FFmpeg process and bounds worker joins; it can truncate the final packet/GOP.

Software `libx264` and NVIDIA `h264_nvenc` both publish H.264 with stereo AAC over RTMP/RTMPS. NVENC does not remove GPU readback, conversion/copying or AAC costs and does not silently fall back to software. The executable is user supplied. Only validated values are used in process arguments; no shell or arbitrary encoder arguments are introduced.

Output intent survives a recoverable session failure and eligible unexpected world loss. `StreamRecovery` waits for complete encoder/readback cleanup, then applies bounded exponential backoff with periodic long cooldowns. Stable actual publishing resets the burst. Invalid config/capability/authentication and unconfirmed cleanup block automatic replacement. Explicit stream off wins over `AutoStart` and `AutoRetry` until a new explicit start.

`EncoderDiagnostics` retains only bounded redacted stderr/exit information. This preserves useful receiver/NVENC failures without putting configured destination/credential components into retained diagnostics. Config and the real FFmpeg process arguments still contain the stream key. Local loopback media transport assumes a trusted machine. Remote receiver playback, actual Unity capture, A/V drift and hardware NVENC remain separate runtime checks.

## Connection recovery and supported scope

`ConnectionRecovery` is opt-in for an initially manual, authenticated observer session. It captures non-secret join metadata independently of opt-in; password retention requires opt-in at the normal password entry. An authorized passwordless session can therefore arm recovery after joining. Recovery uses inspected native game startup/join APIs, preserves credentials only in memory, requires fresh observer authorization and follows bounded retry policy. It does not release read-only restrictions while waiting or silently join as an ordinary player.

Explicit `unattended off` pauses automation and cancels requested output along with connection recovery, while camera coverage can continue. Automation and output then require their own explicit start commands. Native logout/quit cancels those intents even if recovery was disabled and forgets retained credentials. Unexpected connection loss follows the separate recovery path and preserves requested output.

The integration requests background running while unattended intent is armed and restores its prior setting on cancellation. That does not defeat OS sleep, GPU/audio suspension or application termination. In-process reconnection is not an external game/process supervisor. A world disconnect can end RTMP and require a fresh publisher connection after recovery; a healthy ordinary travel does not itself restart output.

No embedded HLS/DASH server, web controller, arbitrary renderer, operating-system login automation or creature simulation authority is added.
